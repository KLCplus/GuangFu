# 系统架构

```text
┌─────────────────────────────┐
│ Vue 3 Web / 微信小程序       │
└──────────────┬──────────────┘
               │ RESTful API
               ▼
┌─────────────────────────────┐
│ Spring Boot 业务后端         │
│ 用户 / 权限 / 电站 / 数据    │
│ 任务 / 报告 / 日志 / 统一响应│
└──────────────┬──────────────┘
               │ HTTP POST
               ▼
┌─────────────────────────────┐
│ Python FastAPI 模型服务      │
│ mock 推理 / 后续真实模型     │
└─────────────────────────────┘
```

MySQL 是 Spring Boot 的业务数据存储；模型服务保持无状态，不直接访问用户与权限数据。

## 调用边界

- Web 和小程序只调用 Spring Boot。
- Spring Boot 通过 `POST /model-api/predict` 调用 FastAPI。
- FastAPI 只校验模型输入、选择模型并执行推理，不承担登录、电站、任务或 API Key 管理。
- 预测任务在后端保留 `PENDING / RUNNING / SUCCESS / FAILED` 状态；骨架阶段同步执行，未来可接入消息队列。

## 前端不直接调用模型服务的原因

1. 权限和 API Key 在统一入口校验。
2. 对客户端保持统一响应、错误码和版本策略。
3. 避免暴露模型拓扑、地址和推理资源。
4. 后端可完整记录预测任务、结果及调用日志。
5. 更换模型实现或扩缩容时不影响客户端。

## 后续演进

第一阶段接入 MySQL 和 JWT；第二阶段接入天气 API、异步任务和结果持久化；第三阶段增加模型版本路由、限流、审计和可观测性。可观测性仅覆盖业务调用，不包含已明确移除的服务器资源监控模块。
