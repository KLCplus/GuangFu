# 需求分析

## 1. 项目范围

系统面向 PC Web、小程序及模型预测服务，提供光伏电站运行数据展示、短期功率预测和综合分析。当前版本是可继续开发的项目骨架，以 mock 数据打通调用链路。

明确不在范围内：服务器 CPU、GPU、内存或其他主机状态监控。

## 2. 功能需求

1. **用户管理**：注册、登录、个人信息、用户启停、角色管理。角色预留 `USER`、`ADMIN`、`API_USER`。JWT 在骨架中预留，暂未签发真实令牌。人脸识别、QQ 登录、微信登录只保留未来扩展说明，不实现真实逻辑。
2. **电站管理**：管理员新增、修改、删除电站；用户查看列表、详情和运行状态。
3. **光伏数据管理**：实时数据、历史曲线、CSV/Excel 上传，以及预测所需的过去 30 分钟数据。持久化接入后需校验时间连续性与缺失值。
4. **天气数据接入**：按电站位置获取当前天气和预报。第三方天气 API Key 只保存在后端环境变量，不下发客户端。
5. **模型预测**：用户选择电站和模型，后端取得输入数据并调用独立模型服务，输出未来 5、10、15、20、25、30 分钟功率。
6. **综合分析报告**：结合电站状态、历史趋势、天气和预测结果生成摘要与建议，第一阶段采用模板规则。
7. **模型 API 开放平台**：申请 API Key、调用开放预测接口、查看调用日志；后续增加配额、过期、禁用和审计。
8. **新闻通知**：管理员发布、编辑、删除新闻或公告；普通用户查看列表与详情。
9. **权限分离**：普通用户使用查询和预测功能；管理员使用 `/api/admin/**`；外部调用方使用 `/openapi/v1/**`。JWT/API Key 接入后由 Spring Security 强制执行。
10. **PC Web + 小程序端**：两端共用 Spring Boot RESTful API；小程序当前只提供目录和请求封装。

## 3. 非功能要求

- Spring Boot 是唯一业务 API 入口，模型服务不直接暴露给前端。
- API 返回结构统一，敏感配置从环境变量注入，不提交真实密钥。
- 模型服务可独立扩缩容，业务模块按 Controller、Service、DTO、VO、Entity 分层。
- 当前使用内存 mock 数据，不承诺重启后的任务数据持久化。
